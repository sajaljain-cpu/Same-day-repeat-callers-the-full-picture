The core finding

One number, two very different problems

Every repeat call falls into one of two families. Either the customer's issue was never resolved (a field or product failure that no agent can fix on the line), or the call itself failed (dropped, no voice, agent error). Each family needs a different owner and a different fix — which is why a single "train the agents" instruction would not move the number.

A
Internet & Field Issues
Internet Supply Down + RDNI (Recharge Done, Internet Not Working)
52%OF REPEATS

Root Cause

Field / dealer does not resolve the connectivity issue in time, and the customer receives no proactive update. So they call again and again only to check status.

Proposed Solution

Tighter coordination with the L2 team to cut dealer turnaround time, plus an automated SMS on ticket open & close (ticket ID + ETA) so the customer never needs to call for a status check.

Why not the call centre

Call audits show agents handled these correctly and gave the right 48–72 hr timeline. The repeat is driven by the field, not the agent.

📞 Audit evidence: Customer 8376821589 called 3 times in one day (from an alternate number) — ticket already open, no partner update received. Agent did everything right; the field had not resolved it.
Owner: L2 Team + Field Ops + Tech (SMS)
B
Disconnected / No Response
Disconnected by CX + No proper response by CX
19%OF REPEATS

Root Cause

The call ended before resolution — dropped, voice too low, or customer unreachable. 82% of these customers call back the same day; many within 15 minutes.

Proposed Solution

A new Ameyo callback queue: any call with talk-time ≤ 30 sec is auto-dialled back. The number sits in an outbound list and is tried as agents free up. ~194 calls/day, handled by 5–6 dedicated agents.

Why this works

These are recoverable interactions — the customer wanted to talk and got cut off. Reaching them first stops them re-entering the main queue as a fresh repeat.

⚡ Audit evidence: 11,724 callbacks happened within 5 minutes of the previous call — clear signs of dropped or failed calls, not genuine new issues.
Owner: CC Ops + Ameyo Admin
C
Voice / Call Quality
Voice Issue — background noise, missing agent opening
3%OF REPEATS

Root Cause

Poor SIP/voice quality on some channels, and occasionally the agent never delivered an opening — so no conversation took place.

Proposed Solution

Route into the same callback queue, plus a SIP channel audit to find the failing channels, and a QA check on agent opening compliance.

Note

Smallest bucket by volume, but high repeat rate (86%). Cheap to fix once the callback queue exists.

🎧 Audit evidence: Multiple calls had heavy background noise with no conversation; one had no agent opening at all while the customer kept saying "hello".
Owner: IT / Infra + QA
D
Wiom Net — Resolution Gaps
UPI payment, sign-in, plan explanation
8%OF REPEATS

Root Cause

Genuine agent / knowledge gaps — agent could not find the root cause of a UPI link failure, or did not explain plan expiry properly. Highest repeat rate of any class (68%).

Proposed Solution

Build resolution scripts for the top 5 Wiom Net codes (agent cannot close until the final step is done) plus targeted agent training with app-team backend access.

Why this works

These are fixable on the first call if the agent has the right path and tools — unlike field issues.

🛠 Audit evidence: Customer 8750582764 — agent could not identify why the recharge link was not arriving (agent error); on the repeat call, plan expiry was not explained well.
Owner: Training + App Team
E
Wiom Refund Follow-ups
Customer chasing a refund, calling repeatedly
SmallBUT ANGRY

Root Cause

Service was not resolved, so the customer escalates to a refund — then calls back repeatedly to chase it, getting angrier each time.

Proposed Solution

A dedicated refund desk / escalation path that owns the case end-to-end, so it is resolved in one touch and the follow-up calls stop.

Note

Low volume but high emotional impact — these are the customers most likely to churn or post negative reviews.

💢 Audit evidence: Customer 7053481285 called 3 times the same day asking about a refund, increasingly frustrated, with the call dropping during the RDNI discussion each time.
Owner: Dedicated Refund Team
Cross-cutting fix

We may be under-counting repeats

🔧 Measure repeats by Customer ID, not phone number

Call audits found customers dialling in from alternate numbers — one customer made three calls from a different phone. Because our repeat metric counts by phone number, these show up as separate "unique" callers, so the true repeat rate is likely higher than reported. Switching the metric to Customer ID (already available in the Ameyo report) will give the real number. Owner: Analytics / MIS.
